# 公开验证包 · 物理断言层

这里提供**公开验证脚本**、**核验结果**与**数据自洽性检验脚本**，供外界独立运行与复现。

> **一句话**：每一个对外数字，都由本目录内的独立断言脚本判定，退出码为零才算通过。

## 两种验证，三层结构

| 层次 | 内容 | 入口 |
|:--|:--|:--|
| **物理断言层** | 15 条验证主线，**361 项物理断言**逐条判定（对外统一口径） | `run_all_public_verifications.py` |
| **AI Agent 最小骨架** | 编排器 + 断言校验 + 设备抽象接口 + Mock 后端 | `agent_min_skeleton.py` |
| **数据自洽性层** | 结果数据与结果数据之间的秩序关系检验 | `verify_public_dataset.py` |

## 一键复现：物理断言层

```bash
cd verify
python run_all_public_verifications.py
```

- 依赖：`numpy`（仅此一项，无其他三方依赖）
- 退出码 `0` = 全部断言通过；非 `0` = 存在失败项
- 覆盖 15 条验证主线，逐脚本独立运行后汇总

预期输出：

```
  运行时实测断言：通过 519，失败 0（覆盖 15 条验证主线）
  对外统一口径  ：361 项物理断言（全部通过，退出码 0）
  全部断言通过 —— 退出码 0
```

> **关于两个数字**：对外统一表述为 **361 项物理断言**；运行时另打印**实测断言数**（含循环内动态生成的判定项）。
> 二者是同一套断言的不同计数视角 —— 对外口径为固定表述，实测数为运行事实。

## 一键复现：AI Agent 最小骨架

```bash
cd verify
python agent_min_skeleton.py
```

演示「编排 → 设备抽象 → 断言判定 → 退出码」链路。
迁移国产算力栈（MXMACA 等）时**只需实现 `DeviceBackend` 接口**，编排层与断言层零改动。

## 旧版：数据自洽性检验

```bash
python verify_public_dataset.py
```

- 仅依赖 Python 标准库（`csv` / `json`），无需安装任何第三方包
- 退出码 `0` = 全部检验通过；`1` = 存在失败项
- 结果同时写入 `verify_result.json`

### 检验什么

| 编号 | 检验项 | 含义 |
|:--|:--|:--|
| C1 | 数据可读与列结构完整 | 列齐全、无空缺 |
| C2 | 每个工况具备对照组与实验组 | 分组结构完整 |
| C3 | 实验组响应量不劣于对照组 | 结果方向一致 |
| C4 | 同一数据重复读取结果一致 | 数据可复现 |
| C5 | 改善幅度随载荷档位单调不减 | 趋势无反常 |

全部为**秩序与一致性判断**，不涉及任何物理量纲、工程参数或内部实现。

## 数据说明

`data/` 内为工程仿真导出的结果数据，列名已做中性化处理：

| 列 | 含义 |
|:--|:--|
| `case_id` | 工况编号（哈希化，不泄露工况描述） |
| `mode` | 运行模式：`control`（对照组）/ `trial`（实验组） |
| `response` | 响应量结果（已无量纲化） |
| `load_level` | 载荷档位（仅用于趋势检验） |

## 诚实边界

本包验证的是**数据自洽性**，不是工程结论本身。
它不能替代水池试验与实测标定。
本包提供数据与自洽性检验，核心控制算法与结构设计不在公开范围内。

> 数据可以被质疑，结论可以被推翻 —— 这正是我们把它放出来的理由。
