## 〇、本版对 V1.0 的三处结构性修正

V1.0 是一份优秀的**招商策划稿**，但作为**保密执行方案**有三处硬伤。V2.0 全部改掉。

| # | V1.0 的问题 | 后果 | V2.0 的修正 |
|---|---|---|---|
| 1 | **L3 级（含 CFD 边界条件、核心参数指标）走 GitHub 公开仓库** | 直接违反《时序闸门》P2「结构与配方永不公开」与 Principle Zero 第一/二道安检 | **L3 从"分级"里移除**，改列**红线层 R（永不披露）**；公开层只留 T1/T2 |
| 2 | 分级按**「谁拿到」**划分（L1 大众 / L2 开发者 / L3 科研） | 同一份文件按收件人分三份 → 传播链失控，且 L3 一旦泄即不可逆 | 分级按**「信息性质」**划分，**获取资格与信息级别解耦**（见 §三） |
| 3 | 3D 资产「直接开放共享」 | GLB/OBJ **顶点坐标即尺寸真值**（GLB 的 JSON chunk 还明文写着 bbox min/max），等于把「宽多少米」交出去 | **归一化后再公开**：包围盒最长边 = 1.0、中心置原点、材质名中性化、元数据清除（已实现并校验） |

> 第 3 条是本次最关键的技术处置。实测：源 GLB 内明文含
> `[-8.9, 6.8, -300.0]` 这类真实米制坐标，**任何人下载后用任意 3D 软件量一下就知道尺寸**。
> 文件名改叫 `floating_tunnel.glb` 是自欺欺人——**几何本身就是答案**。

## 一、红线层 R：三大核心技术的绝对禁区

> **船长指令（2026-11-17）**：
> 「禁止披露三大核心技术：A 动态载荷抵消系统技术和 B 浮体高度恒定潮汐发电技术，
> C 悬浮防波堤消浪发电技术，其它技术可以分级对等共享。」

### R-0 红线定义

| 代号 | 技术 | 公开层可说的最远边界 |
|---|---|---|
| **R-A** | 动态载荷抵消系统 | 只能说「存在一套载荷调节机制，能在恶劣海况下把响应控制在受控微位移区间」 |
| **R-B** | 浮体高度恒定潮汐发电 | 只能说「浮体具备定深悬浮特性，可作为海洋能量装置的载体」 |
| **R-C** | 悬浮防波堤消浪发电 | 只能说「存在消浪与能量收集复合单元，可降低来波冲击」 |

### R-1 红线包含哪些具体内容（**全部禁止出现，含暗示**）

1. **机理与算法**：控制律、反馈拓扑、调节律、状态机、参数整定值
2. **结构与构造**：三大系统专属构件的拓扑、内部腔室布局、构件尺寸
3. **配比与配方**：调载介质/阻尼介质的成分、密度比、级配
4. **边界条件**：CFD 网格策略、入口/出口条件、湍流模型选择、求解器设置
5. **性能真值**：排水量、净浮力、发电效率、载荷抑制比等**具体数值**
6. **专利关联内容**：任何可能落入专利保护范围的结构示意与参数

### R-2 红线的「唯一许可」表述方式

> **只说「做到了什么」，绝不说「怎么做到的」。**

- ✅ 允许：「实现受控微位移，柔性缓冲区间 2–5mm」
- ✅ 允许：「28/28 项指标达标」「K>15」
- ❌ 禁止：「调载舱内填 X 介质，密度 Y，每格配载 Z」

### R-3 与公开层资产的交叉检查（本次实测结论）

| 资产 | 是否触及 R 红线 | 处置 |
|---|---|---|
| 归一化白模（19 个） | **否** —— 几何已无量纲化，不含尺寸/配比/算法 | 进 T2 |
| 公开轨 108s 视频 | **否** —— 字幕层脚本判定 0 命中 | 进 T1 |
| `cap_internal` / `note_internal` 字幕 | **是** —— 19 处尺寸真值 | **禁止外流，存 L3** |
| `sft_geometry_params_v2.json` | **是** —— 全部尺寸与配比真值源 | **禁止外流，存 L3** |
| `04_数据/*.csv`（encoding/layers/modulus/tube/section/weight） | **是** —— 模数、层厚、权重表 | **禁止外流，存 L3** |
| `SINOSFT_Energy` / `SINOSFT_Tsunami_Defense` / `SINOSFT_Control` / `SINOSFT_Materials` | 潜在 | 公开层仅保留**空占位**，不填实质内容 |

## 二、公开层 T：分级对等共享

> 船长指令：「其它技术可以分级对等共享，共同协作发展，AIGC，技术升级等等」

### 2.1 T1 大众层 —— 完全公开、零门槛、免申请

**定位**：面向 AIGC 创作者、美术生、短视频 UP 主、音乐可视化玩家。
**主张**：**先让大众看见，才能有大众来。**

| 资产 | 内容 | 用途 |
|---|---|---|
| 概念图 | 悬浮港全景 / 红树林廊道 / 星空海面 / 管段内部 | 垫图、二创基底 |
| 提示词库 | 中英双语结构化提示词 + 负向词 | 直接喂 Midjourney / SD / Sora / 即梦 |
| 渲染切片 | 公开轨 108s 的 10s 纯工程动态片段 | AI 视频垫图 / 转场 |
| 公开轨长片 | 108s 公开轨成片 | 传播主力 |

**获取**：仓库直接下载，无需申请、无需实名。
**授权**：非商业创作自由使用；商业使用需授权（见 §四）。

### 2.2 T2 开发者层 —— 实名申请制、对等共享

**定位**：面向三维艺术家、游戏开发者、交互工程师、算法研究者。
**主张**：**不给"阶级"，只给"对等"。**

| 资产 | 内容 | 用途 |
|---|---|---|
| 归一化白模 | 19 个 GLB + OBJ + MTL（**无量纲**） | 导入 UE5 / Blender / Three.js 做漫游、场景、交互 |
| 场景规格 | 组装规则、模块语义、色彩标识（**无尺寸**） | 多人协作拼装同一套场景 |
| 接口规范 | 场景墙 A–G 的问题定义 + 评价方法 | 算法极客接入做原型 |

**获取**：填开发者问卷（研究方向 + 用途承诺）→ 专属链接下载。
**为什么是"对等"**：**高校团队、独立开发者、游戏工作室拿到的是同一份白模、同一份规范、同样的权限**——不因身份降级。唯一差别是**追加的贡献深度**（提交 PR 优先获得更高层级的定向邀约），而非**准入门槛**。

> 这是对 V1.0「分级共享」理念的实质性升级：V1.0 按人群分三六九等，本版按**信息性质**分层、按**贡献深度**给回报。

### 2.3 T2+ 定向层 —— 邀约制（**仍然在公开仓库之外**）

**定位**：面向愿意做深度技术协作的团队。
**资产**：可运行的技术原型接口（**不含** R 红线的算法）、数据生成器、评测脚手架。
**获取**：签署 NDA + 说明研究计划 → 定向交付。
**纪律**：**该层物料不进任何公开仓库**，通过带水印/带签名的分发包交付。

## 四、二创授权协议（要点）

1. **非商业**：创作者产出的作品可自由非商业展示、发布、参赛。
2. **商业**：用于商业广告需另行取得授权。
3. **官方收编**：参赛作品一旦被收编进官方 MV，**创作者获得署名 + 永久署名权**。
4. **反向授权（关键）**：创作者授权官方将作品用于 MV 与宣发；官方就参赛作品
   **不主张排他性独家许可**——避免"官方用了你的图就不能你自己用"的争议。
5. **相似侵权**：因使用官方素材而产生的高度近似作品，官方保留追责权。
6. **禁止误导**：不得将素材用于暗示官方背书的商业用途。
7. **R 红线**：授权范围**不含**任何 R 层技术内容；素材本身已做归一化处理，
   不含尺寸与配方。
