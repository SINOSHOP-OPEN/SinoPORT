# 贡献指南（Contributing to SINOSHOP Open Collaboration）

> 欢迎你加入。这一页讲清楚**怎么提 PR**、**什么能提**、**什么不能提**。

---

## 一、我们最看重什么

我们审 PR 不是看代码量，也不是看 star 数。是看一件事：

> **你有没有把别人往前推了一步。**

三种典型的好 PR：
1. **勘误** —— 你按规格拼装时发现比例对不上、说明有歧义、引擎导入炸了。告诉我们。
2. **适配** —— 你把白模在 UE5 / Three.js / Blender 里跑通了，把踩坑与解法写下来。
3. **原型** —— 你把某个场景墙命题（A–G）做成了可运行的东西，哪怕很粗糙。

---

## 二、提交方式

1. **Fork** 本仓库 → 新建分支（命名建议 `feat/<简述>`、`fix/<简述>`、`docs/<简述>`）
2. **提交 PR**，说明：改了什么、为什么、怎么验证的
3. 提交内容必须**自证**：代码给出运行方式；文档给出前后对照；模型给出导入步骤

### Commit Message 规范

```
feat(scope): 简述改动
fix(scope): 简述修复
docs(scope): 简述文档改动
```

示例：
```
feat(ue5): 补充白模导入 UE5 的碰撞体配置说明
fix(spec): 修正管段模块长宽比描述
docs(scene): 补充场景墙 C 的降级状态示例
```

**禁止**在 commit message 里写：具体物理参数、内部编号、修订细节、内部裁定编号。
（详见仓库根目录 `PRINCIPLE_ZERO.md`）

---

## 三、绝对红线（提 PR 前必读）

以下内容**不得**出现在本仓库的任何位置——包括代码注释、文档、模型元数据、
文件名、commit message、Issue、PR 描述：

| # | 禁止内容 | 替代做法 |
|---|---|---|
| 1 | 具体物理尺寸（米/毫米）、容积、重量 | 用「归一化单位」或宏观描述 |
| 2 | 材料配方、控制律参数、标定系数 | 只写效应（如「复合非线性阻尼介质」） |
| 3 | 三大核心技术的机理、算法、边界条件 | **完全不碰** |
| 4 | 内部工程代号 | 用公开名（见 `docs/场景规格与装配规则.md`） |
| 5 | 由素材反推真实尺度的任何提示 | — |

**特别提醒**：提交的模型请使用**归一化口径**（最长边 = 1.0、中心置原点）。
若你在提交中带入了真实尺度，PR 会被直接退回。

> 仓库有自动化安检：commit 与 push 阶段都会扫描。
> **人不能自己给自己判 PASS** —— 判定由脚本做。

---

## 四、代码与文档规范

- **代码**：Python 3.9+ / 遵循 PEP 8；关键逻辑写中文注释说明「为什么」
- **文档**：Markdown；表格用管道对齐；图用相对路径
- **模型**：OBJ + MTL 或 GLB；必须归一化；材质名用 `mat_` 前缀的中性名
- **音频**：WAV 优先；附采样率与声道说明
- **所有提交**：跑一遍仓库自带的校验脚本，全绿再提

---

## 五、许可与署名

- 代码与文档：随仓库许可（见 `LICENSE`）
- 模型与素材：随素材包许可（见 `docs/二创授权协议_V1.0.md`）
- 你的贡献会被记录在提交历史中，**永久可追溯**——这是我们给技术贡献者的
  确权方式，也是我们邀请你加入联合实验的依据。

---

## 六、审查节奏

- 我们**每周**集中审一次 PR（周一）
- 小改动（勘误、措辞）通常 **48 小时内**响应
- 大改动（新增模块、模型）需要**先开 Issue 讨论方向**，避免白做

---

## 七、联系

- 提案、方向讨论 → Issues / Discussions
- 安全问题或红线疑虑 → 私下联系维护者（**不要**公开提 Issue）
- 想进入 T2+ 定向层 → 提交「定向合作意向」，说明你的研究计划与团队背景

---
