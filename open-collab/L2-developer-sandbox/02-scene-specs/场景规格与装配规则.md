## 二、装配规则

### 2.1 归一化口径（**必读**）

每个模型已独立归一化：
- 包围盒**最长边 = 1.0 单位**
- 包围盒**中心置于原点**
- **不含单位**（无米、无毫米）

**因此**：不同模型之间的相对大小**已被有意抹除**。
这是保密要求，也是使用上的一次调整——请自行设定场景尺度。

### 2.2 归一化后各模型的真实长宽比（可用于拼装）

> 下表是**比例**（无量纲），不是尺寸。把任一模型作为基准即可。

| 模型 | X:Y:Z 比例 |
|---|---|
| `tube_module` | 扁圆截面，六边形削平，长径比约 1 : 0.78 |
| `shell_envelope` | 扁椭圆柱，长径比约 1 : 0.13（扁） |
| `tube_bundle` | 扁椭圆柱 × 7 管并列，长径比约 1 : 0.19 |
| `shell_bundle` | 扁椭圆柱，长径比约 1 : 0.13 |
| `deck_box_*` | 长方体，长宽高比约 1 : 0.67 : 0.19 |
| `coupler_*` | 立方体偏扁，约 1 : 0.83 : 0.62 |
| `approach_rail` | 细长梁，断面约 1 : 0.11（极扁） |

### 2.3 拼装建议

```
① 主体：shell_bundle 作为总成基准
② 走廊：corridor_segment 沿 Z 轴首尾相接（端面对齐）
③ 舱体：deck_box_road / deck_box_living / deck_box_rail 置于 tube_bundle 顶部道路面层
④ 连接：coupler_open 置于相邻段接缝处；应急场景换 coupler_closed
⑤ 引桥：approach_rail 从走廊段一端向外延伸，末端可接 scene_pool
⑥ 系泊：scene_mooring 分布于走廊段两侧
⑦ 消浪：wave_break_unit_x 布置于走廊段迎浪侧
```

## 三、场景墙 A–G：可接入的技术命题

> 这七条是**问题定义**，公开可参与。每个命题给出「可开放贡献」与「内部边界」。

### 场景 A · 引桥指纹 → 长时程载荷预测
- **需要**：车辆载荷指纹辨识、多车队列协方差传播、不确定度包络估计
- **技术挂靠**：AI/机器学习、传感、边缘计算
- **可开放贡献**：问题定义、评价方法、合成数据生成器
- **内部边界**：模型结构、传播公式、标定参数

### 场景 B · 预测格点 → 缓存时效管理
- **需要**：格点级缓存、时间-位置-不确定度联合淘汰、邻居协作回退、弱网自治
- **技术挂靠**：分布式存储、边缘缓存、海上通信
- **可开放贡献**：缓存接口规范、命中率分工况统计方法、合成示例
- **内部边界**：预取算法、阈值组合、可执行性标签生成逻辑

### 场景 C · 缓存命中 → 控制决策
- **需要**：前馈 + 预测控制 + 时滞补偿、粗精两级控制分配、分级降级状态机
- **技术挂靠**：控制算法、预测控制、执行器机电
- **可开放贡献**：分层控制框图、降级状态抽象定义、评价指标定义
- **内部边界**：增益、权重、阈值、时滞补偿参数

### 场景 D · 配重粗调 + 作动精调
- **需要**：低频大幅值配重基线调节，连续作动器吸收量化残差与高频扰动
- **技术挂靠**：机电执行器、控制分配、可靠性工程
- **可开放贡献**：粗精协同分层原则、可靠性评价维度
- **内部边界**：配重组合规则、状态控制机构参数、切换时序

### 场景 E · 控制数据 → 仿真复盘与 AI 迭代
- **需要**：结构-水动力耦合建模、场景矩阵验证、故障注入、指标回算
- **技术挂靠**：仿真/数字孪生、HTAP 数据库、AI 训练
- **可开放贡献**：仿真框架接口、场景维度设计、指标回算方法
- **内部边界**：完整场景参数、故障注入实现、真实标定数据

### 场景 F · 工程数据 → 确权存证
- **需要**：仿真文件哈希索引、版本管理、链上锚定引用、收益对账台账
- **技术挂靠**：数据库事务、区块链/时间戳、知识产权管理
- **可开放贡献**：两级存证架构原则（库内索引 + 外部锚定）、哈希字段设计
- **内部边界**：锚定服务选型、具体业务台账参数

### 场景 G · 海上弱网 → 边缘自治
- **需要**：边缘节点本地缓存、异步持久化、通信降级平滑退化、分布式同步
- **技术挂靠**：海上通信、分布式系统、边缘计算
- **可开放贡献**：降级场景描述、边缘自治架构原则
- **内部边界**：协议参数、同步策略细节

> **分层边界提示**：实时控制内环不进入数据库层。数据库抖动不允许穿透到控制回路。
> 找到自己该在的层，比抢"最内层"更有用。

## 四、参与方式

1. **取包**：填开发者问卷（研究方向 + 用途承诺）→ 获取下载链接
2. **复现**：按本规格拼装场景，截图或录屏
3. **提交**：向仓库提 PR（修正规格错误、补充场景方案、提交你的原型）
4. **深化**：表现出色者获定向邀约，进入 T2+ 受控层与联合实验

**期待什么样的 PR**：
- 规格勘误（比例对不上、装配规则有歧义）
- 新的场景接入方案（把某个 A–G 命题做成可运行原型）
- 引擎适配经验（UE5 / Three.js / Blender 的导入踩坑与解法）
