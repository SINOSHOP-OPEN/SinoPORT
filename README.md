# SinoPORT · 可移动抗台风悬浮港生态社区

> **一座会整港迁移的抗台风悬浮港，兼作海洋生态社区。**
>
> 无桩基· 可拖航 · 消浪 25× · 九泊位 · 波浪能自供 · 红树林共生


---

## 一、这个项目解决什么问题

固定港口有两个**结构性**缺陷，不是工程量能弥补的：

| 缺陷 | 后果 |
|---|---|
| **桩基沉箱**打桩定位，**位置一旦确定就不能改** | 台风路径偏移时，港口只能被动挨打 —— 重建一次要数年 |
| 防波堤是**漫反射**的硬墙 | 浪从开口进来后仍在泊位区扩散，泊位仍需承受残余波浪 |

SinoPORT 的回答是三条，**每条都对应一个行业痛点**：

| # | 技术 | 解决的痛点 | 关键指标 |
|---|---|---|---|
| **1** | **模块化浮体**（无桩基） | 港口位置不可变 | 整港**向海迁移 1,200 m**；消除锚链/桩基/海床地基 |
| **2** | **消浪金字塔 132 孔** | 硬墙只能反射浪 | 外浪 **15 m → 内浪 < 0.6 m**（**25×**） |
| **3** | **七层仿生复合材料 + 悬浮红树林** | 海上构筑物维护成本高、且破坏底栖生态 | 等效密度 **620~650 kg/m³**（混凝土 1/4）；**零海床接触** |

> **可移动不是概念，是可执行的工程动作。**
> 岸边景观片已实测演示整港向海迁移全过程 —— 见 §7 演示流程。

## 二、为什么是「生态社区」而不只是「港口」

港口不是孤立的建筑，**它是一片可移动的海洋社区基础设施**：

| 社区要素 | 实现 | 参数来源 |
|---|---|---|
| **消浪** | 金字塔斜面 7 排 132 孔（D900）进水 | 实测 **R450 面 = 132** |
| **净水** | 波浪被吸进而非反射 → 港区水面平静 → 藻类与鱼群可驻留 | 外浪 15 m → 内浪 < 0.6 m |
| **供能** | 三区段波浪能捕获 + 潮汐发电水舱 | 定位为**辅助能源**（传感器/照明/通信） |
| **生态共生** | 悬浮红树林 MGR-LIVE **173 组**（3 树种：秋茄/桐花树/白骨壤） | 编码规范 §4.15 |
| **人居** | 27 栋悬浮房屋沿环形水道分布+ 18 艘球船 | 编码规范 §4.16/4.17 |
| **抗台风** | 外浪 15 m 设计工况，衰减 25× | 编码规范 §28 |

**设计哲学**（SINOSHOP 体系）：
> **「海生电、电养船、船搭桥、桥造城、城惠民」**

## 二·五 ★ 集成式多级活水生态通道（本项目的拓扑级创新）

### 弃「外挂鱼道」，用「集成生态通道」

**传统做法**：外挂独立鱼道（如七级结构）。
- ❌ 占额外空间—— 平面与剖面都要为通道让位
- ❌ 易受风浪破坏 —— 独立结构，与主体**不同寿命**
- ❌ 需额外模具 —— 独立构件 = 独立制造链

在抗台风场景下最致命的是第二点：
会形成「**鱼道先坏、主体尚好**」的独立失效模式 ——
抗台风受力结构还在，生态连通已经断了。

### 本方案：融入承重结构的柱墙阵列

> 传统独立鱼道（如七级结构）占用额外空间且易受风浪破坏；
> 本方案将其**升级**为融入承重结构的 **10 柱 5 墙** 与 **6 柱 3 墙** 阵列。
> **墙体既承担抗台风受力，其预留孔洞又构成多级活水生态通道**，
> 实现**结构承重与生态连通的拓扑级融合**。

| 模块 | 阵列 |
|---|---|
| MOD-STD（27×27×8 m） | **10 柱 5 墙** |
| MOD-DM（27×27×6 m） | **6 柱 3 墙** |

### 实测：集成后贯通面积反而更大

| 通水路径 | 规格 | 贯通面积 |
|---|---|---|
| 承重预留孔洞 | 12 直通榫卯柱 φ300 mm | 0.8482 m² |
| 压载水舱三管束 | φ2000 mm × 3（V6.0） | 9.4248 m² |
| **合计** | — | **10.2730 m²** |

| 指标 | 值 |
|---|---|
| 被移除外挂鱼道（φ2000 单管） | 3.1416 m² |
| **倍数** | **3.27 倍** |
| **透水率**（迎水面投影 729 m² 口径） | **1.4092%** |

> **口径声明**：1.4092% 为**几何实算**，
> **非 CFD 实测的流量交换率** —— 两者物理量不同，我们不混充。
> 复算：`python demo_evolution.py`（纯 Python，秒级出结果）

### 一套模具，三个痛点

| 痛点 | 外挂鱼道方案 | **本方案** |
|---|---|---|
| 抗台风 | 鱼道单独承受，易损 | 墙体本身受力，通道寄生其中 |
| 模块组装 | 需额外接口与模具 | **榫卯柱阵列即接口** |
| 生态通水 | 独立构件，单独维护 | **同套模具同时解决** |

> **一句话**：不是给港口加了一条鱼道，
> 而是**让港口的承重结构本身就是鱼道**。

### 3.2 材料

| 层 | 材料/结构 | 功能 | 参数 |
|---|---|---|---|
| **L7** | 荷叶仿生超疏水涂层 | 自清洁、抗附着 | 接触角 ≥150°，厚 100 μm |
| **L6** | 鲨鱼皮微结构 | 减阻、抑菌 | 减阻 8~17% |
| **L5** | 竹塑玄武岩纤维复合材料 | 抗冲击、承载 | 拉伸 ≥180 MPa |
| **L4** | 中空钢桁架（Q690） | 主承力 | 减重 40~50% |
| **L3** | 纤维混凝土（C80~C100） | 抗压、耐久 | 50~80 MPa |
| **L2** | 复合泡沫浮力材料 | 永久浮力 | 380~420 kg/m³ |
| **L1** | 环氧陶瓷密封涂层 | 防腐防水 | 寿命 ≥30 年 |

**等效密度 620~650 kg/m³** —— 混凝土的 1/4，这是「可拖航」的物理前提。

## 四、架构

```
SINOPORT/
├── src/
│   ├── specs/                ← ★ 参数源：全部红线与几何的唯一权威
│   │   ├── pyramid_spec_r6.py    金字塔开孔（斐波那契 7 排 / D900） 26/26
│   │   ├── bw_geometry.py        半圆防波堤六段径向 + 9 开口
│   │   ├── berths_spec_r2.py     9 泊位 + 距弧余量9/9
│   │   └── shore_spec_r2.py      岸边四季（冬夏双状态）  23/23
│   ├── model/← 几何生成
│   │   ├── build_pyramid_r6.py       FreeCAD 参数化建模（132 孔）
│   │   └── film_engine.py            自研软件光栅化（免 GPU）
│   └── verify/
│       └── verify_frames.py帧序列连续性硬门
├── docs/
│   ├── standards/← 编码规范 5,279 行 / 45 章
│   └── reports/               ← 脚本产出的校验报告
└── .github/                   ← 治理
```

**设计原则：参数源是唯一权威。**
几何、渲染、校验**全部从 `src/specs/` 派生**，不允许硬编码散落。
参数一改，几何与判据同步生效 —— 这就是「可运行、可测试」的根基。

## 五、快速开始

### 5.0 ★ 从零复现（评委推荐路径，3 条命令）

```bash
git clone https://gitee.com/sinoshop/SinoPORT.git
cd SinoPORT
python -m venv .venv
```

激活虚拟环境：

```bash
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
```

安装依赖并运行演示：

```bash
pip install -r requirements.txt
python demo.py
```

**预期输出**：

```
演示结论：4 / 4 步 PASS  （总耗时 5.33 s）
```

末尾会自动打印 6 行硬指标（金字塔 132 孔 / 防波堤 381 m / 泊位余量 334.9 m 等）。

> `demo.py` **只需 NumPy**，不需要 FreeCAD、不需要 GPU、不需要 Blender。
> 任何一项 FAIL 都会返回非零退出码 —— 便于 CI 集成。

```bash
python demo_evolution.py
```

预期看到 `3.1416 m2-> 10.2730 m2   倍数 3.27 倍   透水率 1.4092%`。

```bash
python src/specs/pyramid_spec_r6.py     # VERIFY: 26/26 PASS
```

## 六、可验证性（**本项目最强的差异点**）

**每一个数字都有脚本背书，没有一个是手写的。**

| 断言 | 实现方式 | 实测 |
|---|---|---|
| 金字塔 132 孔全通 | 统计 R450 圆柱面数 | **132 = 132** ✅ |
| 建模实体合法 | OCC `isValid()` | `True` ✅ |
| 挖除量符合基准 | 体积差 vs 标定基准 | 27.1726 / 26.7581（**+1.55%**）✅ |
| 9 泊位含于半圆内 | 逐泊位算距弧余量 | 最小 **334.9 ≥ 300** ✅ |
| 帧序列连续 | `verify_frames.py` | 零跳号 ✅ |

### 6.1 一个反例，说明我们不走过场

孔径从 1,000 mm 改为 900 mm 时，若按面积（D²）外推基准，
实测比值是 **0.8609 而非 0.8100** —— 因为孔径变小使**间隙变宽**
（357 → 450 mm），相邻圆柱的斜切体**重叠更少**。

最终采用**实测标定系数 K = 0.8609**，偏差从 **+7.93% 收敛到 +1.55%**。

> **几何一改，基准必须重新标定。**
> 这就是「参数化 + 实测闭环」的真实含义 ——
> 不是把参数写进文件，而是**每次改动都重新验证并更新判据**。
